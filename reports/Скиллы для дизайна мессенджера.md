# Собираем дизайн-стек мессенджера из скиллов

Единого скилла, который закрывал бы Liquid Glass, Material 3 Expressive, динамические цвета и анимации сразу на Android и в вебе, нет. Лучший результат даёт связка из 4–6 узких скиллов. **Для Android на Kotlin/Compose** основу составляют **aldefy `compose-expert`**: это Compose, MotionScheme, shared elements и predictive back, а примеры кода в нём проверяются компиляцией в CI. К нему добавляется **hamen `material-3`**: Material You, dynamic color и аудит UI, 1.5k звёзд. Из **официального Google `android/skills`** стоит выборочно взять `navigation-event`, `edge-to-edge` и `jetpack-compose-performance`. **Для Liquid Glass** все варианты молодые, сделаны энтузиастами и почти без звёзд. Самый практичный из них **xenitV1 `apple-liquid-glass`**: он единственный покрывает и веб (SVG-рефракция), и Compose (через Haze). Если нужна настоящая линзовая рефракция на Android, к нему добавляется **Kashif-E `kmp-liquid-glass`**. **Для веба** главный выбор по анимациям — **скиллы Эмиля Ковальски** (51.1k звёзд). Аудит UX проводит **Vercel `web-design-guidelines`**, переходы между экранами — `react-view-transitions`. Material-токены даёт тот же `material-3`. Есть два слабых места. Генерацию динамической палитры в вебе через `material-color-utilities` не описывает ни один проверенный скилл, а M3 Expressive и spring-анимации в Material Web не реализованы. Эти части придётся писать самим или оформить собственным скиллом.

## Для Compose хватает трёх скиллов, и один из них от Google

Сильнее всего для Android выглядит **`compose-expert` Адита Лала** (598 звёзд, MIT, v2.4.0 от 2026-07-08). В нём 301 строка SKILL.md и 27 справочных файлов: `material3-motion.md`, `animation.md`, `theming-material3.md`, `navigation.md`, `performance.md`, `lists-scrolling.md` и выдержки из исходников androidx. Начиная с версии 2.4.0 он покрывает `MaterialExpressiveTheme` и MotionScheme. По объёму материала о движении у него нет конкурентов: **213 упоминаний MotionScheme/Expressive API, 93 — predictive back, 30 — SharedTransitionLayout/sharedElement**. Главное его отличие в том, что CI компилирует фрагменты кода из документации и прогоняет Robolectric-тесты на утверждения о раскладке. Так отлавливаются устаревшие и «галлюцинированные» API, которыми обычно грешат скиллы ([aldefy/compose-skill](https://github.com/aldefy/compose-skill), [SKILL.md](https://raw.githubusercontent.com/aldefy/compose-skill/master/skills/compose-expert/SKILL.md)).

Дизайн-систему закрывает **`material-3` Ивана Морджилло** (CWTI Ltd, 1.5k звёзд, MIT, релиз v1.1.1 от 2026-06-29). Это специализированный скилл по Material 3 / Material You: токены, 30+ компонентов, layout, M3 Expressive и доступность. Цвету отведены отдельные файлы `theming-and-dynamic-color.md` и `color-system.md`. Скилл уже учитывает обновления **Google I/O 2026**: expressive layout scaffold, сетку 8dp, обновлённые списки, меню и поиск, а также шкалу Expressive-форм. Он принимает аргументы `[component|theme|layout|scaffold|audit]`, поэтому годится и для ревью готовых экранов. Слабость у него обратная, чем у aldefy: анимации он почти не описывает (0 упоминаний shared elements, 1 — predictive back) ([hamen/material-3-skill](https://github.com/hamen/material-3-skill)).

Третий компонент — **официальные скиллы Google** из `android/skills` (Apache-2.0, около 10k звёзд, последний коммит 2026-10-26, 36 скиллов). Отдельного скилла по Material 3 для телефонов среди них нет, есть только `wear-compose-m3` для Wear OS. Зато Google закрывает места, критичные именно для мессенджера ([android/skills](https://github.com/android/skills), [обзор Android skills](https://developer.android.com/tools/agents/android-skills)). **`navigation-event`** — авторитетный источник по анимациям Predictive Back через `NavigationBackHandler` и по миграции с `BackHandler` на SDK 36+ ([SKILL.md](https://raw.githubusercontent.com/android/skills/main/navigation/navigation-event/SKILL.md)). **`edge-to-edge`** решает проблемы с IME-инсетами, то есть с поведением поля ввода сообщения при открытой клавиатуре ([SKILL.md](https://raw.githubusercontent.com/android/skills/main/system/edge-to-edge/SKILL.md)). **`jetpack-compose-performance`** нужен для длинных LazyColumn с историей чата ([SKILL.md](https://raw.githubusercontent.com/android/skills/main/jetpack-compose/jetpack-compose-performance/SKILL.md)). Для планшетов и складных устройств пригодятся `adaptive` и `navigation-3`.

Остальные кандидаты играют вспомогательную роль. **`m3-expressive`** из ahmed3elshaer/everything-claude-code-mobile — единственный скилл, посвящённый только M3 Expressive: 2008 строк, 28 expressive-компонентов, морфинг форм, spring-физика. Но его Gradle-настройка устарела (BOM `2025.05.00`, `kotlinCompilerExtensionVersion` вместо Compose Compiler-плагина Kotlin 2.x). Поэтому его стоит использовать только как каталог компонентов, а папку копировать отдельно, не ставя весь плагин из ~40 скиллов ([SKILL.md](https://raw.githubusercontent.com/ahmed3elshaer/everything-claude-code-mobile/main/skills/m3-expressive/SKILL.md)). **`claude-android-ninja`** от Drjacky (129 звёзд, коммит 2026-09-29) лучше всех описывает `dynamic*ColorScheme` (22 упоминания) и хорош как архитектурный каркас: MVVM, Hilt, Room 3, Navigation3, offline-first. В дизайне он неглубок ([Drjacky/claude-android-ninja](https://github.com/Drjacky/claude-android-ninja)). Скилл `mobile-android-design` из популярного wshobson/agents (41.9k звёзд) получился общим, без MotionScheme и shared elements ([wshobson/agents](https://github.com/wshobson/agents)). Скиллы new-silvermoon короткие (compose-ui занимает 49 строк) и Expressive не затрагивают ([new-silvermoon](https://github.com/new-silvermoon/awesome-android-agent-skills)). Главное практическое предупреждение: если одновременно поставить несколько общих Compose-скиллов (compose-expert, modern-jetpack-compose, android-ninja, mobile-android-design), они начнут конкурировать за активацию. **Общий Compose-скилл должен быть один.**

| Скилл | Сильная сторона | Чего нет | Установка |
|---|---|---|---|
| aldefy `compose-expert` | MotionScheme, springs, shared elements, predictive back, Expressive | Мало про dynamic color (4 упоминания) | `/plugin marketplace add aldefy/compose-skill` → `/plugin install compose-expert` |
| hamen `material-3` | M3/Material You, dynamic color, Expressive-формы, аудит | Анимации | `npx --yes skills add hamen/material-3-skill --skill material-3 -y` |
| Google `navigation-event`, `edge-to-edge`, `jetpack-compose-performance` | Predictive back, клавиатура, производительность списков | M3-дизайн | `android skills add <name> --project=.` |
| `m3-expressive` (опционально) | Каталог 28 Expressive-компонентов | Актуальная сборка, shared elements | Скопировать папку в `.claude/skills/` |

## Liquid Glass держится на скиллах с десятком звёзд

Liquid Glass — самая незрелая часть ландшафта. Найдено не меньше 13 настоящих SKILL.md, но все они созданы в 2026 году одиночными авторами, и **в официальном anthropics/skills ничего подобного нет**. Большинство скиллов к тому же нацелены на SwiftUI и iOS 26: haider-nawaz (71 звезда, самый популярный), `liquid-glass-design` из affaan-m/everything-claude-code, zakisheriff. Для Kotlin и веба они бесполезны ([haider-nawaz](https://github.com/haider-nawaz/liquid-glass-skill), [Skillselion](https://skillselion.com/skills/affaan-m/ecc/liquid-glass-design)). Звёзд у всех от 0 до 138, так что о качестве лучше судить по свежести и конкретике кода, чем по популярности.

Обе платформы пользователя покрывает только **xenitV1 `apple-liquid-glass`** (381 строка, MIT, коммиты от 12 октября 2026, 11 звёзд). Он объясняет правила Apple HIG: двухслойную модель «контент и хром», варианты regular и clear glass, фолбэки для Reduce Motion, Reduce Transparency и Increase Contrast. Для веба он содержит готовые `tokens.css` и `refraction.js`. Это SVG displacement-фильтр, который в Chromium по-настоящему преломляет живую страницу, а в Safari и Firefox работает в режиме «mirror mode» ([репозиторий](https://github.com/xenitv1/liquid-glass-skill)). Для Compose в нём есть рецепт на **Haze `haze-glass` 2.0.1** из реально выпущенного приложения. Этот API экспериментальный и требует Android 13+. Скилл явно предупреждает, что источник должен быть непрозрачным, а API в нём сверены 2026-10-12 ([platforms.md](https://raw.githubusercontent.com/xenitV1/liquid-glass-skill/main/references/platforms.md)).

Для настоящей линзовой рефракции на Android лучше подходит **Kashif-E `kmp-liquid-glass`** (402 строки, Apache-2.0, библиотека с 138 звёздами и 296 коммитами). Его написал мейнтейнер Compose Multiplatform-порта библиотеки AndroidLiquidGlass от Kyant0. Скилл учит агента API `backdrop`: источник `Modifier.layerBackdrop`, стекло через `drawBackdrop`, порядок эффектов, blur, lens, vibrancy, progressive blur, SDF. Есть рецепты карточек, диалогов и таб-баров. Поддержка по уровням API такая: **с API 31 доступны blur и цвет через RenderEffect, с API 33 — полный набор через AGSL RuntimeShader, ниже API 31 эффекты молча отключаются**. Зависимость `io.github.kashif-mehmood-km:backdrop:0.0.1-alpha02` пока в альфе, так что API будет меняться ([SKILL.md](https://raw.githubusercontent.com/Kashif-E/KMPLiquidGlass/master/plugins/kmp-liquid-glass/skills/kmp-liquid-glass/SKILL.md)). Если приложение только под Android и используется оригинальная библиотека Kyant0, концепции переносятся без изменений, но имена пакетов другие. Готового скилла от самого Kyant0 или от chrisbanes/haze нет, поэтому разумно адаптировать скилл Kashif-E под себя.

В вебе лучше всего проработан дизайн у **Armitanemati `liquid-glass-claude-skill`** (538 строк, MIT, сентябрь 2026). В нём описаны уровни материала от thin до clear, проверка контраста на худшем фоне, фолбэки через `@supports`, `prefers-reduced-transparency`, `forced-colors`, линзирование краёв через `feImage` внутри `backdrop-filter`, баги движков и замеры производительности. Его стоит использовать для проверки доступности. Для Android он честно предупреждает, что RenderEffect размывает собственный контент view, а не то, что под ним ([репозиторий](https://github.com/Armitanemati/liquid-glass-claude-skill)). **stormaref `liquid-glass`** (91 строка, MIT, 14 звёзд) даёт компактный готовый CSS и SVG-рефракцию. Его директива написана под Angular, для React или Vue её придётся портировать ([репозиторий](https://github.com/stormaref/LiquidGlassSkill)). Остальные варианты проигрывают. `glassmorphism` из sickn33 сидит в огромной коллекции (~46k звёзд), но описывает стекломорфизм в стиле 2021 года без рефракции ([skillsdirectory](https://www.skillsdirectory.com/skills/sickn33-glassmorphism-agentic-awesome-skills)). ShiotanNeco требует API 36+ и не имеет лицензии ([репозиторий](https://github.com/ShiotanNeco/android-liquid-glass)). Aks-4125 по сути сводится к системе тонированных поверхностей ([SKILL.md](https://raw.githubusercontent.com/Aks-4125/kmp-glassmorphism-skill/master/SKILL.md)).

Для мессенджера есть общее правило, которое подтверждают несколько скиллов. **Стекло кладут на хром интерфейса (верхнюю панель, таб-бар, поле ввода, bottom sheets), а не на пузыри сообщений.** Прокручиваемая лента под стеклом означает постоянную нагрузку на GPU, о чём предупреждают и Kashif-E, и xenitV1. Устройствам ниже API 31 нужен сплошной или тонированный фолбэк.

## В вебе анимации сильны, а Material You слаб

С веб-анимациями ситуация обратная: здесь работают зрелые и массово используемые скиллы. Для мессенджера лучше всего подходит **набор Эмиля Ковальски** `emilkowalski/skills` (51.1k звёзд, MIT). Автор работал в Vercel и Linear и написал Sonner. Скилл `emil-design-eng` (674 строки, 396.5K установок) описывает выбор easing, длительностей и spring-анимаций (`{type:"spring", duration, bounce}`, `useSpring`) и объясняет, когда анимировать не нужно. Скилл `review-animations` (263.6K установок) вызывает пользователь, чтобы отревьюить уже написанные анимации. В наборе есть также `mobile-native` для мобильного веба (баг 100vh, safe areas, зум при фокусе на input) и `animation-performance` ([README](https://raw.githubusercontent.com/emilkowalski/skills/main/README.md), [skills.sh](https://skills.sh/)). Именно этот набор подходит для микровзаимодействий чата: отправки сообщения, шторок, тостов.

Аудит выполняет **Vercel `web-design-guidelines`** (797.2K установок, #55 на skills.sh). Это тонкая обёртка, которая во время работы скачивает актуальные Web Interface Guidelines и выдаёт замечания в формате `file:line`, поэтому ей нужен доступ в сеть. Её соседка **`react-view-transitions`** (332 строки, MIT) — лучший проверенный скилл по View Transitions API: `<ViewTransition>`, shared-element и направленные переходы при навигации, переупорядочивание списков ([vercel-labs/agent-skills](https://github.com/vercel-labs/agent-skills)). Библиотечный скилл выбирают под свой стек. Для GSAP есть **официальный `greensock/gsap-skills`** (17.4k звёзд, MIT, 8 скиллов), но учтите вендорский перекос: он советует GSAP по умолчанию ([README](https://raw.githubusercontent.com/greensock/gsap-skills/main/README.md)). Для Motion (бывший Framer Motion) официального скилла от motion.dev нет. Лучшие варианты — secondsky `motion` (516 строк, React 19 / Next 16) ([SKILL.md](https://raw.githubusercontent.com/secondsky/claude-skills/main/plugins/motion/skills/motion/SKILL.md)) и 199-biotechnologies `motion-dev-animations`, который последний раз обновлялся в ноябре 2025 и мог устареть ([SKILL.md](https://raw.githubusercontent.com/199-biotechnologies/motion-dev-animations-skill/main/SKILL.md)).

Самые популярные дизайн-скиллы, `frontend-design` от Anthropic (около 1.0M установок) и `design-taste-frontend` от Leonxlnx (694.9K), заточены под маркетинговые страницы и hero-секции, а не под интерфейс чата ([anthropics/skills](https://github.com/anthropics/skills), [taste-skill README](https://raw.githubusercontent.com/leonxlnx/taste-skill/main/README.md)). Они полезны для лендинга мессенджера, но не для самого веб-клиента. Для интерфейса приложения разумнее взять **ui-ux-pro-max** (142.1k звёзд). Он работает через локальную базу из 192 палитр, 119 UX-правил и 22 стеков и покрывает экраны приложений ([репозиторий](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)). Ни один проверенный скилл не заточен специально под чат-интерфейсы.

Material You в вебе остаётся главной дырой. Единственный проверенный скилл здесь — тот же **hamen `material-3`**, и сам он называет поддержку веба «limited». Он сопоставляет токены с CSS-переменными `--md-sys-*` и показывает импорты `@material/web`. Генерацию схемы он лишь отсылает к `@material/material-color-utilities` и прямо предупреждает: **Material Web находится в режиме поддержки, M3 Expressive в вебе не реализован, spring-физики и морфинга форм там нет** ([SKILL.md](https://raw.githubusercontent.com/hamen/material-3-skill/master/skills/material-3/SKILL.md)). Скилл intense-visions по HCT-палитрам виден только на агрегаторах и не проверен ([claudepluginhub](https://www.claudepluginhub.com/skills/intense-visions-harness-claude/design-material-design-3)). Получается, что «плавность» в вебе дают скиллы Эмиля и Motion, а не Material.

## Итоговая конфигурация для мессенджера

| Задача | Android (Kotlin, Compose) | Веб |
|---|---|---|
| Material 3 / Material You | hamen `material-3` | hamen `material-3` (токены `--md-sys-*`) |
| M3 Expressive | `compose-expert` + каталог `m3-expressive` | Нет: в Material Web не реализовано |
| Динамические цвета | hamen `material-3` (`theming-and-dynamic-color.md`) | Нет проверенного скилла, нужен свой на `material-color-utilities` |
| Плавные анимации | `compose-expert` (MotionScheme, springs, shared elements) | Emil Kowalski + `react-view-transitions` + Motion или GSAP |
| Predictive back, клавиатура, списки | Google `navigation-event`, `edge-to-edge`, `jetpack-compose-performance` | Emil `mobile-native` |
| Liquid Glass | xenitV1 (Haze) + Kashif-E `kmp-liquid-glass` (AGSL, API 33+) | xenitV1 (SVG-рефракция) + Armitanemati (доступность) |
| Аудит | `material-3 audit` | Vercel `web-design-guidelines` |

Все эти репозитории сопровождает в основном один автор, а Liquid Glass-скиллам всего несколько месяцев. Поэтому скиллы лучше **копировать в `.claude/skills/` репозитория (vendoring)**, а не тянуть живые обновления. Так изменения проходят через ревью, а набор остаётся компактным и скиллы не мешают друг другу при активации.

## Conclusion

Ландшафт асимметричен, и это определяет, где тратить собственные усилия. Android-сторона в целом закрыта: Google поставляет системный слой, aldefy и hamen — дизайн и движение. Веб-анимации тоже закрыты зрелыми скиллами с сотнями тысяч установок. Пробелы остались на стыке двух платформ. Нет единого источника динамической палитры, который давал бы одинаковые цвета в Compose (`dynamicColorScheme`) и в вебе (`material-color-utilities` → CSS-переменные). Нет и общего языка стекла и движения. Поэтому самое ценное вложение — **собственный небольшой скилл дизайн-системы мессенджера**. В нём стоит зафиксировать seed-цвет и пайплайн генерации токенов для обеих платформ, правило «стекло только на хроме» с фолбэками по уровням API и для `prefers-reduced-transparency`, а также общие spring-параметры. Сторонние скиллы при этом остаются справочниками по API.

Оговорка о достоверности: исследователи не могли пользоваться GitHub code search и API, поэтому небольшие скиллы могли выпасть из обзора. Это особенно касается Liquid Glass для Compose и HCT-палитр для веба. Звёзды и даты сняты 2026-10-28. Альфа-статус библиотеки backdrop и экспериментальный `haze-glass` означают, что Liquid Glass на Android пока остаётся ставкой на будущее, а не стабильной основой. Для релиза мессенджера безопаснее начать с Haze-размытия и сплошных фолбэков, а рефракцию включать на устройствах с API 33+.
